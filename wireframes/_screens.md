# Forge — Екрани головного flow · Замовлення на вайрфрейми

*Scope: тільки MAIN JOB — J3 + J4 (атлет знає що тренувати сьогодні і логує виконання).*
*Джерела: sitemap.md (назви і ролі), flows.md (місце у flow), jtbd.md (job-формулювання).*
*Наступний крок: на базі цього документа малюємо lo-fi вайрфрейми.*

## Відібрані екрани

Критерій включення: екран **закриває job** з jtbd.md **і** стоїть на критичному шляху flows.md → MAIN JOB.
Виключено: Вхід (prereq без job), тренерські екрани (крок 8), харчування і прогрес тіла (крок 8).

### 1. Сьогодні — план на день `[A]`

**Job (J3):**
> Коли я прийшов на тренування, я хочу відкрити одне місце і одразу побачити вправи, підходи і відпочинок на сьогодні, щоб не гаяти перші 10 хвилин на пошук плану.

**Місце у flow:** home screen атлета — 0 тапів від запуску. Перший екран після авторизації. Точка входу в J4. Без нього J3 не закривається взагалі (SPOF #1, sitemap.md).

**Стани:**

| Стан | Реальний? | Чому |
|---|:---:|---|
| Завантаження | ✓ | Явно у flow: `G("Завантажуємо план...")` — блокує UI поки план не підтягнувся |
| Порожній | ✓ | Два під-кейси: (1) тренер не підключений → `F: "немає тренера — введи інвайт-код"`; (2) тренер підключений, але план ще не призначений → `M: "план не призначено — чекаємо від тренера"` |
| Помилка | ✓ | `I("Помилка мережі")` — не вдалось завантажити план; атлету пропонується retry |
| Успіх | — | Показати план = нормальний стан екрана, не окремий момент «вийшло». Окремого success-екрана тут немає. |

**Ключовий елемент:** CTA «Почати тренування» — з'являється лише коли план є. Без нього вхід у J4 неможливий.

---

### 2. Активне тренування / Логер `[A]`

**Job (J4):**
> Коли я відпочиваю між підходами в залі, я хочу записати вагу і кількість повторень за 5–10 секунд, щоб до кінця тренування мати точні дані, а не реконструювати по пам'яті.

**Місце у flow:** 1 тап від Сьогодні (CTA «Почати тренування»). Цикл: вправа → підхід → зберегти → таймер відпочинку → наступний підхід. Виходить тільки після всіх вправ → Завершення тренування. Без нього J2 порожній (тренер не бачить даних).

**Стани:**

| Стан | Реальний? | Чому |
|---|:---:|---|
| Завантаження | — | Екран відкривається з уже завантаженим планом зі Сьогодні. Нічого додатково не підтягується при вході. |
| Порожній | ✓ | `R("Стан: поля порожні — кнопка Зберегти неактивна")` — поки вага і повтори не заповнені, основна дія заблокована. Це in-screen empty: поля введення без значень. |
| Помилка | ✓ | `U("Помилка збереження підходу")` — збій при записі сета; атлету пропонується retry. Якщо відмовляється — `Z4: "дані підходу втрачено"`. |
| Успіх | — | Збереження підходу не дає окремого «успіх»-екрана. Атлет залишається на Логері (запускається таймер → наступний підхід → продовження циклу). |

**Ключовий елемент:** кнопка «Зберегти підхід» — єдина дія. Неактивна поки хоча б одне поле порожнє. Це J4 в одній кнопці.

### 3. Завершення тренування `[A]`

**Job (E2 · M):**
> E2 — Коли я відпахав важке тренування і нікому про це не розповів, я хочу щоб тренер побачив це без мого звіту, щоб не відчувати що стараюсь у вакуумі.
> M — план і виконання в одному місці: тренер може коригувати, атлет завжди знав що робити.

**Місце у flow:** після останнього підходу останньої вправи → CTA «Завершити тренування» → цей екран. Термінальна точка MAIN JOB. Тут замикається петля: факт виконання стає видимим для тренера.

**Стани:**

| Стан | Реальний? | Чому |
|---|:---:|---|
| Завантаження | — | Flow показує прямий перехід AB → AC без loading state. Збереження Workout Log — мікро-операція, не блокуючий стан екрана. |
| Порожній | — | Недосяжний: до цього екрана можна дійти лише після виконання всіх підходів. Немає сценарію де він відкривається «порожнім». |
| Помилка | — | У flow немає гілки помилки для цього переходу — відкрита діра (зафіксована в critique flows.md). В MVP: якщо збереження впало — показати toast, але не окремий error-стан екрана. |
| Успіх | ✓ | Це єдиний явний success-екран у MAIN JOB flow: `SUCCESS1(("Успіх: тренування залоговано"))`. Показує: тривалість тренування, список вправ, нові PRs. Закриває E2: зусилля зафіксовані і тренер їх побачить. |

**Ключовий елемент:** якщо атлет побив особистий рекорд — PR badge на екрані. Це мікро-момент мотивації (E2) і підстава продовжувати (J5 preview).

## Примітки для вайрфреймера

- **Сьогодні** має два різних порожніх стани — верстати окремо: (a) без тренера = інвайт-промпт; (b) без плану = «тренер ще не призначив».
- **Логер** — мобільний first. Поля введення мають бути великими (пальці, зал). Кнопка «Зберегти підхід» — full-width, максимально досяжна.
- **Завершення** — єдиний success-момент у flow. Заслуговує на «відзнаку»: анімація, PR badge, час тренування. Не мінімізувати.
- Стан «Помилка» у Логері (збій збереження підходу) — критичний: людина між сетами, концентрація на залі. Retry має бути одним тапом, без навігації.

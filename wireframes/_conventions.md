# Forge — Конвенції вайрфреймів

*Ці правила обов'язкові для всіх екранів. Виняток — тільки якщо явно зазначено у файлі конкретного екрана.*

---

## 1. Деталізація

**Що показуємо:** структура, ієрархія блоків, зони взаємодії.
**Що не показуємо:** колір (крім сірого), шрифтові гарнітури, тіні, іконки, ілюстрації, брендинг, анімації.

- Палітра: білий фон `#ffffff`, рамки і лінії `#cccccc`, заповнені зони `#e8e8e8`, текст `#333333`
- Плейсхолдери для графіків, фото і складних візуалізацій — сірий прямокутник `background:#e8e8e8` з підписом що саме там буде:

```html
<div class="placeholder" aria-label="графік ваги за 8 тижнів">
  графік ваги за 8 тижнів
</div>
```

- Іконки позначаємо текстом у квадратних дужках: `[←]`, `[✕]`, `[+]`, `[≡]`
- Рекорди, досягнення, гейміфікація — тільки як зона-плейсхолдер: `<div class="placeholder">PR badge — «Новий рекорд! Присідання 95 кг»</div>`

---

## 2. Розмітка

Семантичний HTML5. Не використовуємо `<div>` там, де є семантичний тег.

| Зона | Тег |
|---|---|
| Верхня шапка з назвою екрана і навігацією | `<header>` |
| Нижня навігація (bottom nav) | `<nav>` |
| Основний вміст | `<main>` |
| Логічна секція всередині main | `<section>` |
| Картка вправи, картка атлета, картка їжі | `<article>` |
| Форма введення (вага, повтори, їжа) | `<form>` |
| Таблиця підходів / повторів | `<table>` + `<thead>` + `<tbody>` |
| Кнопки дій | `<button type="button">` або `<button type="submit">` |
| Навігаційні посилання | `<a>` |
| Поля введення | `<label>` + `<input>` (завжди разом) |

`<div>` та `<span>` — тільки для чисто стилістичних обгорток де семантики немає.

## 4. Назви файлів

Базовий стан екрана = `<назва>.html`. Окремий файл на кожен нестандартний стан.

### Формат
```
wireframes/<назва>.html          ← базовий (happy path / success)
wireframes/<назва>-empty.html    ← порожній стан
wireframes/<назва>-error.html    ← помилка
wireframes/<назва>-loading.html  ← завантаження
```

### Всі файли головного flow (крок 7, `_screens.md`)

| Файл | Що показує |
|---|---|
| `today.html` | Сьогодні — план на день, план є і завантажено |
| `today-loading.html` | Сьогодні — план завантажується |
| `today-empty-no-trainer.html` | Сьогодні — тренер не підключений, інвайт-промпт |
| `today-empty-no-plan.html` | Сьогодні — тренер підключений, план не призначений |
| `today-error.html` | Сьогодні — помилка мережі при завантаженні плану |
| `workout.html` | Активне тренування / Логер, поля заповнені, кнопка активна |
| `workout-empty.html` | Логер — поля порожні, кнопка «Зберегти підхід» неактивна |
| `workout-error.html` | Логер — помилка збереження підходу, retry |
| `finish.html` | Завершення тренування — успіх, підсумок і PR badge |

## 5. Стани — окремий файл, спільна структура

Кожен стан — окремий `.html`. Структура сторінки (header, nav, main, секції) однакова. Змінюється лише вміст main.

**Правила:**
- Базовий файл (`today.html`) = успішний стан (план є, дані завантажено)
- `-empty` — нульовий вміст + CTA або підказка «що робити далі»
- `-error` — повідомлення про помилку + кнопка retry
- `-loading` — ті самі зони що в базовому, але заповнені skeleton-плейсхолдерами (`<div class="placeholder skeleton">`)
- Не дублюємо HTML-структуру вручну — у вайрфреймах достатньо коментаря `<!-- структура ідентична today.html -->` якщо розмітка не змінюється

## 6. Ролі

Атлет і тренер — окремі файли. Ніколи не в одному.

- Атлет: `today.html`, `workout.html`, `finish.html`, `nutrition.html`, `progress.html`
- Тренер: `trainer-clients.html`, `trainer-athlete.html`, `trainer-feedback.html`, `programs.html`, `program-builder.html`
- Спільні екрани (реєстрація, вхід, профіль): `register.html`, `login.html`, `profile.html` — без префікса ролі, але всередині позначено для якої ролі який варіант

## 7. Mobile-first

Вайрфрейми проєктуємо під ширину **390 px** (iPhone 14 / baseline mid-range Android).

```css
/* wireframe base */
body {
  max-width: 390px;
  margin: 0 auto;
  font-family: sans-serif;
  font-size: 16px;
  color: #333;
  background: #fff;
}
```

- Bottom nav — фіксований знизу (`position: fixed; bottom: 0`)
- Header — фіксований зверху (`position: fixed; top: 0`)
- Main — відступи зверху і знизу щоб не ховатись під fixed-елементи
- Touch targets — мінімум 44×44 px для всіх інтерактивних елементів (кнопки, поля, nav-пункти)
- Десктопна версія — окремий крок, окремі файли або медіа-запит — після узгодження mobile

## 8. Що лишаємо на потім

Ці елементи у вайрфреймах **відсутні або замінені плейсхолдером**:

| Елемент | У вайрфреймі |
|---|---|
| Кольорова палітра | Тільки сірий |
| Шрифтові гарнітури (DM Serif, Inter) | `font-family: sans-serif` |
| Тіні, blur, backdrop | Відсутні |
| Іконки (SVG, бібліотека) | Текст у дужках: `[←]`, `[+]` |
| Реальні фото і аватари | `<div class="placeholder">фото атлета</div>` |
| Анімації і переходи | Відсутні |
| PR badge, streak, досягнення | `<div class="placeholder">PR badge — зона</div>` |
| Графіки прогресу (Charts.js) | `<div class="placeholder">графік ваги за 8 тижнів</div>` |
| Темна тема | Тільки світла |
